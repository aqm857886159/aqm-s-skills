# 两种典型用户旅程

这六个 Skill 既可以单独触发，也可以围绕同一份证据组合。组合时保留每条证据的来源和采集状态，不把一个连接器的失败扩散成整个任务失败。

## 旅程一：研究员 + 开发者 + 创作者决定下一个选题

### 用户起点

> 我既做 AI 产品又做内容。结合最近论文、值得学习的开源仓库和 B站观众问题，给我下个月最值得做的三个选题，不要只追热点。

### 完整流程

1. `paper-evidence-radar` 把问题拆成近期方法、架构机制和可运行评测三条检索线，保留论文日期、代码成熟度和复现成本。
2. `github-repository-research` 在指定 revision 上追踪一条真实调用链，判断哪些能力已实现、哪些只是 README 声明，并检查许可证和最小复用单元。
3. `bilibili-content-research` 匿名读取指定 BV 的公开元数据、字幕和有限评论，明确样本数、缺失字幕和接口错误。
4. `wechat-chat-export` 先验证当前微信数据库确实可读；从未接入时先说明“高风险、非必要不要尝试”，再提供调试副本、用户本人 LLDB、重新登录触发和逐库 HMAC 验证的完整方法，最后按群和时间范围导出默认匿名的本地记录。旧 JSON 存在不等于当前接入健康。
5. `creator-opportunity-radar` 建立带采集日期和来源类型的证据目录，拒绝不存在的 evidence ID，再从论文、仓库、B站和微信证据中形成“可靠需求 + 差异化押注 + 低成本实验”三个选题。

```text
论文证据 ─┐
仓库能力 ─┼─> 可追溯机会卡 ─> 三项内容组合 ─> 先验证，再制作
B站/微信 ─┘
```

### 用户得到什么

- 不是热门词列表，而是三个带证据 ID、信心等级和缺口的机会；
- 每个机会都有最小验证动作、成功证据和停止条件；
- 如果 B站评论失败，论文、仓库和已有反馈仍能形成低置信度结果，缺失来源会显示在报告顶部；
- Skill 不会替用户发布、排期、私信或复制其他创作者的表达。

### 验收路径

- arXiv：实时限量查询和本地 Atom fixture 都能标准化版本、日期与主分类；
- GitHub：对本仓库真实运行快照，返回 revision、状态、许可证和测试目录；
- B站：匿名、无 cookie 获取公开视频及一页有限评论；
- 微信：`doctor` 实际打开当前 contact/message 数据库，真实导出默认匿名、限量、`0600` 的 JSON；
- 机会排序：来源类型从证据目录推导，伪造/不存在的 evidence ID 无法制造高置信度；
- 组合旅程：实时论文、实时 B站、公共 GitHub、本机微信和本地视频五个来源实际进入同一个机会排序。

## 旅程二：产品负责人 + 剪辑师诊断“黑屏、无声、接入消失”

### 用户起点

> 导入的视频双击能预览，但画布是黑的而且没有声音。我的历史反馈还在，微信接入状态却没了，这会不会让以前的数据和其他人的接入都失效？

### 完整流程

1. `wechat-chat-export` 先运行 `doctor`，把“已保存的历史 JSON”和“当前数据库是否真能解密”列成两个事实。当前接入失败不会删除旧数据，但会降低新反馈的覆盖和新鲜度。
2. 就绪后按相关反馈群和问题时间窗真实导出记录，默认匿名并保留稳定证据 ID；未就绪时不拿旧记录冒充新鲜数据，只展示风险方法，由用户亲自确认和执行取钥命令。
3. `reference-video-deconstruction` 在本地用 FFprobe 检查容器、视频流、音频流和方向，再对全时长做有限亮度采样、对最多 120 秒音轨做音量检测并抽取有限帧。视频不会上传。
4. 如果本地解码样本有可见像素范围，问题范围从“源文件全黑”缩小到应用侧资产 URL/blob 生命周期、codec/CORS、media readiness 或 canvas draw path；“有音轨但低于信号阈值”和“有信号但目标应用静音”分别处理。
5. `github-repository-research` 只在用户提供代码库时沿素材导入、预览和画布渲染的真实调用链定位第一处失败，不从症状直接猜根因。
6. 最终报告分别给出素材证据、应用证据、连接器状态、历史数据可信边界、建议修复和回归步骤。

```text
历史数据状态 ─┐
连接器健康   ─┼─> 覆盖边界
视频流/音轨  ─┤
本地解码帧   ─┴─> 第一处失败 ─> 最小修复 ─> 真实预览/画布回归
```

### 用户得到什么

- 明确回答旧数据是否仍可使用，以及哪些结论因为连接器离线而不再新鲜；
- “源文件无音轨”“能解码但应用没画出来”“有音轨但播放状态静音”是三个独立结论；
- 诊断报告只声称实际检查过的层，不用“可能是 codec”冒充根因；
- 修复后的验收同时覆盖双击预览、画布播放、音频、时间轴和重新打开项目。

### 验收路径

- 用 FFmpeg 真实生成带 H.264 画面和 AAC 音轨的 MP4；
- 再生成纯黑画面 + 数字静音 MP4，验证亮度和音量检测能与正常视频区分；
- 提取器确认音轨、尺寸、帧率、均匀采样范围并输出有限帧和 source hash；
- 微信真实私有冒烟测试确认当前库可解密、记录可导出、作者默认打码、输出权限为 `0600`；
- 失败接口返回 `partial` 或 `failed` 及缺失范围，不泄露 traceback，也不把历史数据标记为删除。
