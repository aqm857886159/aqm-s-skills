# 案例：连接微信，能帮一个团长每天多接住几单

> 一条把"连接微信"讲成真实价值的样例。面向在 Work Buddy / Codex 这类桌面 Agent 里使用 Skill 的商家与运营者。文中数据为合成演示数据，人物与聊天均为虚构，用于展示能力而非真实客户。

## 一、痛点：钱就漏在没人回的那几条消息里

芳姐在小区里卖水果，手上三个客户群：1 号院、2 号院、还有一个老客户 VIP 群。每天群里几百条消息滚过去——接龙、晒图、问价、催货、偶尔一条投诉。晚上收摊，她想翻一遍谁还没回，可消息已经刷到看不到头。

这不是她一个人的处境，是被反复验证过的痛点：

- 私域服务商微伴助手在自己的营销文里直接点名："客户讨论时提到'最近有优惠吗？''想试驾新款'，这些关键商机很容易被快速滚动的群消息淹没"，并给出"单日未被及时回复的客户消息可达 5-10 条""约 15% 的潜在客户在一个月内静默流失"这类数字（[微伴博客](https://weibanzhushou.com/blog/34283)）。
- 整条私域 SCRM 赛道（微伴、探马、句子互动）都把产品建在这个痛点上——但它们**要求企业微信、按年付费**。像芳姐这样用**个人微信群**的团长、个体商家，恰恰在这套工具覆盖不到的地方。全国私域电商 2025 年交易规模约 6.4 万亿、用户 6.8 亿（网经社），仅快团团就有 600 万+ 团长。

漏一条"多少钱""想买"，就是漏一单。痛点直接连着钱。

## 二、案例运行：收摊后一条指令，五分钟出一份经营周报

场景是桌面端的 Work Buddy / Codex。芳姐已经用 `wechat-chat-export` 把自己有权访问的三个群、上一周的记录，只读导出成了本地 JSON（这一步的风险与边界见第五节）。她只需要说一句：

> "把我这三个客户群上周的记录出一份经营周报，我在群里叫'芳姐'。谁的提问没人回、有哪些想买的、有没有投诉要处理，给我能直接发的话术。"

`wechat-group-insights` 接手，背后发生的是一条"脚本负责数、模型负责判断"的流水线：

1. **确定性统计**（`group_stats.py`）：消息量、参与人数、每日活跃、消息类型、疑问句数量——这些数字全部由脚本从导出文件里数出来，不经过模型，杜绝"大概几百条"式的编造。
2. **语义判断**（模型按 [`insights-contract.md`](../skills/wechat-group-insights/references/insights-contract.md) 产出）：哪些客户提问在导出窗口内一直没等到芳姐回复、哪些是真实购买意向、哪条投诉还悬着、每条该怎么回。
3. **核验渲染**（`render_report.py`）：把判断渲染成一份单文件 HTML 周报。**关键机制在这里**——报告里每条结论都必须引用一个证据 ID，渲染器会拿它去导出文件里逐一核对，时间、原话、上下文都从真实数据里取；只要有一个 ID 不存在，整份报告拒绝生成。这让"AI 瞎总结"在结构上无法发生。

生成的周报（可打开 [`assets/sample-weekly-report.html`](assets/sample-weekly-report.html) 亲自看）长这样：

- **顶部一句话结论 + 四个 KPI**：本周三个群 93 条消息，大部分订单接住了；但 6 条客户提问无人回应，其中两条来自最安静的 VIP 群，合计约两千元的企业订单正在等回复。KPI 分别是：未回复提问、购买意向、风险投诉、今天该跟进的件数。
- **本周最该做的 5 件事**（按优先级）：排第一的是 VIP 群里"楠楠"问的中秋礼盒 20 盒——周日先问果篮、周一晚追问礼盒，约两千元，中秋档期临近，报价晚一天就少一分胜算。每张卡片都能**点开"上下文"看到群里的原话**，下面附一条**可一键复制的建议话术**，且话术只承诺芳姐真实说过的东西（价格没定就说"今天把报价发您"，绝不替她编个价格出去）。
- **没人回复的客户提问 / 购买意向线索 / 风险与投诉** 三张清单：每条都带"已等 N 天"的徽章（由渲染器按真实时间戳算，不是模型说的），点开即是证据原文。坏果投诉那条被标为高风险、"已等 2 天"。
- **群活跃概览**：每个群一条迷你柱状图 + 一句话点评。VIP 群消息最少却含金量最高——两条企业订单线索都在这里，建议每天睡前专门过一遍。
- **数据范围与边界**：老老实实写清楚——2 条语音读不了内容、图片只记为 `[image]`、只覆盖导出的 3 个群。页脚一行"证据校验 25/25 通过"。

芳姐不用读一条聊天记录，就知道今天开门前该先给谁回话。

## 三、为什么这条链路成立

- **只读的限制，在这个场景里不是限制。** 经营复盘天然是"事后"的：收摊后跑一次、输出待办给人去跟进，恰好落在"只读导出 + 本地文本分析"的舒适区。不能实时提醒、不能自动群发，在这里反而更稳、更合规。
- **诚实的边界，是可信的来源。** 报告不声称分析了语音和图片，不把截断的覆盖伪装成完整；每条结论都能点回原话。商家敢照着它去跟客户说话，是因为它没有一处在替他吹牛。
- **它填的是市场空白。** SCRM 服务不了个人微信群；而"个人年度报告""AI 总结群聊"这些做烂了的角度都是娱乐向的。面向经营者、每条结论可追溯的**客户群周报**，是有需求证据却没人做成的那一格。

## 四、把价值链打通：让 Codex 帮你把话回出去

周报只解决了"知道该做什么"。最后一公里——真正把话回给客户——由 `wechat-followup-assist` 用 **computer use** 接上。这是 Codex 桌面端 computer use 好用的地方：它能直接操作芳姐**本人已登录**的微信桌面客户端可见界面。

交互被刻意设计得慢而稳，因为发出去的每一句都是以芳姐的名义、发给她真实的客户：

1. Agent 把要发的内容列成带编号的清单：目标群、收件人、逐字最终话术。芳姐挑她认可的第几条，可以改词，改完再看一遍定稿。
2. 选执行模式：**默认"放入输入框"——Agent 只把话术粘好，发送键由芳姐自己按**；她也可以对某几条明确说"这几条帮我发"，才会进入代发。
3. 逐条执行：每发一条前，Agent 会**先截图核对当前打开的会话标题**，确认是"幸福里1号院"而不是"2号院"才动手（最坏的错误是把对的话发进错的群，这一步专门堵它）；粘贴用的是原话，不改写。
4. 单次最多 10 条、一次一个会话、拒绝"发到我所有群"式群发；没有 computer use 工具时，降级成"逐条复制到剪贴板 + 告诉你粘到哪个群"的清单，绝不谎称已经发了。

到这里，"连接微信"这件事的价值链是完整的：**读（把沉在群里的聊天变成本地数据）→ 判断（变成能追溯的经营决策）→ 行动（在你确认下把决策落地）**。

## 五、诚实的边界（这部分不能省）

- **首次接入是高风险流程。** 让 AI 读到自己的微信，前提是 `wechat-chat-export` 的一次性取钥——这是非官方、版本相关（当前审查路径为 Apple Silicon + 微信 4.1.x）、存在封号/签名/隐私风险的调试流程。**非必要不要尝试**；Agent 不会替你确认风险、运行 `sudo`/LLDB、登录登出账号或修改官方微信。日常经营用的商家，通常只在自己电脑上做一次。
- **只读、本地、不外传。** 导出、统计、周报全部在本机生成并以 `0600` 写盘，默认打码发送者，拒绝写进任何 Git 工作区，不上传、不回写微信。发送与跟进永远是人点头才发生。
- **能力有硬边界。** 读不了语音/图片/视频的内容；看不到导出范围外的消息，也无法证明某个问题是不是在私聊里回过；不按营收给群排序，不下结论超过证据能支撑的范围。报告里的"数据范围与边界"就是用来把这些盲区摆到明面上的。
- **这是给授权数据用的工具。** 面向的是"梳理自己有权访问的客户群"，不是监控、不是爬别人的数据。

顺带一提，这个赛道 2025 下半年经历过一轮法律清洗（chatlog 收到官方函件下架、腾讯集中 DMCA 了一批导出仓库）。我们的姿态——只读、本地、显式风险确认、不发消息不上传、诚实标注边界——正是这条链路能长期站得住的原因，也是它和"破解教程"的根本区别。

## 六、开源

三个微信 Skill（`wechat-chat-export`、`wechat-group-insights`、`wechat-followup-assist`）连同另外五个研究/创作 Skill 一起开源，可组合、可独立安装、各自带脚本、`references/` 契约与 `evals/`：

```bash
# 装这条经营链路的三件套
npx skills add aqm857886159/aqm-s-skills \
  --skill wechat-chat-export wechat-group-insights wechat-followup-assist
```

周报的证据核验、统计与渲染都有可重复的离线测试覆盖（含"编造证据 ID 必须中止渲染"这条防幻觉门）。欢迎照着 [`insights-contract.md`](../skills/wechat-group-insights/references/insights-contract.md) 换成你自己的行业话术，或把周报模板改成你想要的样子。

## 附：用户旅程走查（自评）

站在芳姐的视角，从头到尾数一遍她经历的节点，以及每个节点是否"简单、看得懂、知道自己该干嘛"：

| 节点 | 她看到/要做的 | 顺不顺 | 处理方式 |
|---|---|---|---|
| 1. 想分析群，但没导出过 | 说一句"帮我分析客户群" | ⚠️ 会被引导去做一次性高风险取钥，这是唯一的重门槛 | Skill 明确告知"高风险、非必要不尝试"，且只需一次；演示/内容从"已接入"讲起，不把门槛塞给读者 |
| 2. 导出 | 选群、选时间范围 | ✅ 一条命令，默认打码、限量、写在 Git 外 | 脚本负责，边界在回复里说清 |
| 3. 出周报 | 说一句自然语言 + 报出自己群里的名字 | ✅ 五分钟出图，KPI 一眼看懂 | 统计交脚本、判断交模型、渲染做核验 |
| 4. 读周报 | 打开 HTML | ✅ 顶部一句话结论 + 4 个 KPI，先讲结果；细节可逐层点开 | 设计上"一眼专业"：报头、KPI、优先级卡片、证据引用、活跃图、边界说明 |
| 5. 跟进 | 挑几条、过目、发送 | ✅ 默认自己按发送，核对会话标题，小批量 | computer use 逐条确认，缺工具降级剪贴板 |
| 6. 下周复用 | "下周再来一份" | ✅ 同一条命令可复用，可配合定时 | Skill 主动提示这两个下一步 |

**结论**：除了第 1 个节点（首次取钥）是微信 4.x 现实带来的、无法抹平的安全门槛之外，其余每一步都是"一句话触发 + 一眼看懂结果"。内容与演示应从"已接入"开始，把首次取钥单独作为诚实前提交代，而不是让它挡在价值前面。周报本身在桌面浏览器和手机上都验证过：桌面是四栏 KPI + 双线报头的经营简报质感，手机自动降为两栏、标题优雅换行，都保持专业观感。
